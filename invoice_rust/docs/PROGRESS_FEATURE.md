# 实时进度显示功能说明

## 功能概述

发票识别工具现已支持实时进度显示，用户可以在处理过程中看到：
- 文件总数统计
- 实时完成数量
- 可视化进度条
- 完成百分比
- 实时日志更新

## 功能特性

### 1. 即时文件统计

点击"开始识别"后，程序会立即扫描目标目录并统计需要处理的文件总数。

```
📊 检测到 500 个文件待处理
```

### 2. 实时进度条

在配置区域的开始按钮下方显示动态进度条：

```
进度: 156/500                           31%
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**显示内容：**
- 左侧：当前完成数/总文件数
- 右侧：完成百分比
- 中间：绿色进度条动态增长

### 3. 批量日志更新

每处理 10 个文件或达到总数时，自动输出进度日志：

```
✓ 已处理 10/500 个文件 (2%)
✓ 已处理 20/500 个文件 (4%)
✓ 已处理 30/500 个文件 (6%)
...
✓ 已处理 500/500 个文件 (100%)
```

### 4. 多线程非阻塞处理

- 处理任务在后台线程运行
- 主界面保持响应，不会卡顿
- 通过消息通道实时传递进度信息
- 用户可以随时查看日志和进度

## 技术实现

### 架构设计

```
┌─────────────┐       ┌──────────────┐       ┌──────────────┐
│   GUI 线程   │ ◄───── │  消息通道     │ ◄───── │  处理线程     │
│  (主线程)    │       │ (Progress)   │       │ (后台线程池)  │
└─────────────┘       └──────────────┘       └──────────────┘
      │                                              │
      │ 实时更新UI                                   │ 并行处理
      │ - 进度条                                     │ - 32线程
      │ - 统计数字                                   │ - 文件提取
      │ - 日志输出                                   │ - 信息识别
      └──────────────────────────────────────────────┘
```

### 消息类型

```rust
pub enum ProgressMessage {
    /// 开始处理
    Started { total: usize },
    
    /// 文件处理完成
    FileCompleted { 
        filename: String, 
        completed: usize, 
        total: usize 
    },
    
    /// 处理完成
    Finished,
    
    /// 日志消息
    Log(String),
}
```

### 核心流程

1. **初始化阶段**
   ```rust
   // 创建进度通道
   let (progress_tx, progress_rx) = mpsc::channel();
   
   // 启动后台处理线程
   thread::spawn(move || {
       process_invoices_with_progress(
           &base_path,
           buyer_kw,
           Some(&output_path_buf),
           Some(thread_count),
           Some(progress_tx),  // 传入发送器
       )
   });
   ```

2. **处理阶段**
   ```rust
   // 发送开始消息
   sender.send(ProgressMessage::Started { total: 500 });
   
   // 并行处理，每完成一个文件发送进度
   files.par_iter().for_each(|file| {
       // 处理文件...
       
       let completed = counter.fetch_add(1, Ordering::SeqCst) + 1;
       sender.send(ProgressMessage::FileCompleted {
           filename: file.name,
           completed,
           total: 500,
       });
   });
   
   // 发送完成消息
   sender.send(ProgressMessage::Finished);
   ```

3. **UI更新阶段**
   ```rust
   // GUI主循环中检查进度
   fn check_progress(&mut self) {
       while let Ok(msg) = progress_receiver.try_recv() {
           match msg {
               Started { total } => {
                   self.progress.total = total;
               }
               FileCompleted { completed, total, .. } => {
                   self.progress.completed = completed;
               }
               Log(msg) => {
                   self.log(msg);
               }
               Finished => {
                   self.progress.is_active = false;
               }
           }
       }
   }
   ```

## 性能优化

### 1. 批量日志输出

为避免频繁更新导致性能下降，采用批量输出策略：

```rust
// 每10个文件或最后一个文件时输出日志
if completed % 10 == 0 || completed == total {
    sender.send(ProgressMessage::Log(
        format!("✓ 已处理 {}/{} 个文件 ({}%)", ...)
    ));
}
```

**优势：**
- 减少消息发送频率
- 降低UI刷新开销
- 保持日志清晰可读

### 2. 原子计数器

使用 `AtomicUsize` 实现线程安全的计数：

```rust
let completed_count = Arc::new(AtomicUsize::new(0));

// 多线程安全地更新计数
let completed = completed_count.fetch_add(1, Ordering::SeqCst) + 1;
```

**优势：**
- 无锁并发，性能高
- 保证计数准确性
- 适合高并发场景

### 3. 非阻塞UI

```rust
// 使用 try_recv() 而不是 recv()
while let Ok(msg) = rx.try_recv() {
    // 处理消息...
}
```

**优势：**
- 不会阻塞主线程
- 保持界面流畅响应
- 即使消息堆积也不会卡顿

## 常见问题

### Q1: 进度显示不准确怎么办？

**A**: 进度基于文件数量统计，如果某些文件处理时间特别长，可能会出现进度条停滞的情况。这是正常现象，程序仍在处理中。

### Q2: 为什么日志不是每个文件都输出？

**A**: 为了保持界面清爽和性能，采用批量输出策略（每10个文件输出一次）。如需查看每个文件的详细信息，可以在完成后查看Excel文件。

### Q3: 进度条能取消处理吗？

**A**: 当前版本暂不支持取消功能。一旦开始处理，将会处理完所有文件。未来版本会考虑添加取消按钮。

### Q4: 处理很快时看不到进度条？

**A**: 如果文件数量少且处理速度快（如只有几个文件），进度条可能一闪而过。这是正常的，说明处理已完成。
