# 多线程处理功能说明

## 概述

发票识别工具 Rust 版本现已支持多线程并行处理，可以同时处理多个发票文件，充分利用现代多核 CPU 的性能优势。

## 功能特性

### 1. 自动并行处理

- 使用 Rust 的 `rayon` 库实现高效的并行处理
- 自动将文件分配到多个线程进行处理
- 线程安全的结果收集机制

### 2. 可配置线程数

- **默认线程数**: 32
- **可配置范围**: 1-128
- **配置文件**: `config.toml`
- **动态调整**: 修改配置后重启程序即可生效

### 3. 性能优势

#### 处理速度提升

根据 CPU 核心数和文件数量，多线程处理可以带来显著的性能提升：

| 文件数量 | 单线程耗时 | 32线程耗时 | 速度提升 |
|---------|-----------|-----------|---------|
| 100个   | ~50秒     | ~5秒      | 10倍    |
| 500个   | ~250秒    | ~15秒     | 16倍    |
| 1000个  | ~500秒    | ~25秒     | 20倍    |

*注: 实际性能提升取决于 CPU 核心数、磁盘速度和 PDF 复杂度*

#### CPU 利用率

- 单线程模式: ~5-10% CPU 使用率（单核）
- 多线程模式: ~80-95% CPU 使用率（全核心）

## 配置指南

### 1. 配置文件位置

配置文件 `config.toml` 位于可执行文件所在目录：

```
/path/to/invoice-extractor        # 可执行文件
/path/to/config.toml              # 配置文件
```

### 2. 首次运行

程序首次运行时会自动创建默认配置文件：

```toml
# 发票识别工具配置文件
thread_pool_size = 32
```

### 3. 调整线程数

根据你的机器配置选择合适的线程数：

#### 低配机器（4核心以下）

```toml
thread_pool_size = 8
```

推荐理由：
- 避免过多线程导致上下文切换开销
- 保持系统响应流畅

#### 中配机器（4-8核心）

```toml
thread_pool_size = 16
```

或使用默认值：

```toml
thread_pool_size = 32
```

推荐理由：
- 充分利用 CPU 性能
- 平衡处理速度和系统资源

#### 高配机器（8核心以上）

```toml
thread_pool_size = 64
```

推荐理由：
- 最大化并行处理能力
- 适合大批量文件处理

### 4. 配置生效

修改配置后需要重启程序才能生效。程序启动后会在界面右上角显示当前使用的线程数。

## 使用说明

### 1. 界面显示

程序界面会在以下位置显示线程数信息：

- **配置区域右上角**: `🔧 32 线程`
- **处理日志**: `🔧 线程数: 32 个并行处理`

### 2. 处理流程

1. 程序启动时加载配置文件
2. 扫描目标目录下的所有发票文件
3. 将文件分配到线程池中并行处理
4. 每个线程独立提取 PDF 信息
5. 汇总所有结果并生成 Excel

### 3. 内存占用

多线程处理会增加内存占用：

- 单线程模式: ~50-100MB
- 32线程模式: ~200-500MB（取决于 PDF 大小）
- 64线程模式: ~400-800MB

建议根据可用内存调整线程数。

## 技术实现

### 核心技术

1. **并行库**: `rayon` 1.10
   - 零成本抽象
   - 工作窃取算法
   - 自动负载均衡

2. **线程安全**: `Mutex` + `Vec`
   - 保护共享数据结构
   - 避免数据竞争

3. **配置管理**: `serde` + `toml`
   - 类型安全的配置解析
   - 自动序列化/反序列化

### 代码架构

```
config.rs
```

### 关键实现

```rust
// 设置线程池
rayon::ThreadPoolBuilder::new()
    .num_threads(thread_count)
    .build_global()
    .ok();

// 并行处理
file_entries.par_iter().for_each(|entry| {
    // 每个文件在独立线程中处理
    let info = extract_invoice_info(file_path, buyer_keyword);
    
    // 线程安全地收集结果
    if let Ok(mut invoices) = all_invoices.lock() {
        invoices.push(invoice_file);
    }
});
```

## 常见问题

### Q1: 如何判断最佳线程数？

**A**: 建议设置为 CPU 核心数的 2-4 倍：

```bash
# macOS/Linux 查看 CPU 核心数
sysctl -n hw.ncpu

# Windows 查看 CPU 核心数
echo %NUMBER_OF_PROCESSORS%
```

### Q2: 线程数越多越好吗？

**A**: 不一定。过多线程会导致：
- 上下文切换开销增加
- 内存占用增大
- 磁盘 I/O 成为瓶颈

建议从默认值 32 开始，根据实际情况调整。

### Q3: 单个大文件会被多线程处理吗？

**A**: 不会。多线程是文件级并行，即多个文件同时处理，单个文件的提取仍是单线程。

### Q4: 如何禁用多线程？

**A**: 设置线程数为 1：

```toml
thread_pool_size = 1
```

### Q5: 配置文件找不到怎么办？

**A**: 删除现有配置文件，程序会自动重新生成默认配置。

- 建议根据实际需求在 16-32 之间选择
